# 闲鱼与小红书 Web 链接监控系统开发技术文档

版本 2.0 · 开发评审稿 · 2026 年 11 月 22 日

## 1 项目目标与首期范围

把闲鱼和小红书链接放进同一个 Web 监控池。运营人员粘贴商品或店铺链接，后台自动识别平台、定时记录页面可观测的指标，并在销量、价格或商品状态达到规则时发出提醒。打开详情可查看历史变化、原始展示值和采样时间。浏览器关闭后，后台继续运行。

首期按个人或小团队使用设计。上一版的 Windows 采集器作为可选上游，提供批量导入入口。日常新增链接、查看历史、设置提醒和处理失败均在 Web 完成。

| 平台与目标 | 首期监控指标 | 默认频率 |
| --- | --- | --- |
| 小红书商品 | 累计展示销量、小时及日增量、价格、可确认的商品状态 | 10:00–23:00 每小时一次，含首尾共 14 槽 |
| 小红书店铺 | 页面可确认的全店累计展示销量、相邻日差值 | 每日 10:00 |
| 闲鱼商品 | 价格、页面可确认的在售／已售／下架状态、链接可用性 | 建议沿用商品时段，数据源验证后确认 |
| 闲鱼卖家主页 | 首期可录入并按样本验证。若可以稳定获取商品集合，展示观察范围内的可见商品数、新出现及移出列表的商品 | 建议每日 10:00，字段验证后启用 |

闲鱼如能从可用来源获取语义明确、连续可比的累计销量，再为相应目标开启销量型规则。“已售”只产生状态变化事件。若样本可稳定读取“想要人数”，可先作为独立字段展示。卖家主页列表变化按商品 ID 比较，仅在两次快照的排序、筛选及分页覆盖范围一致且读取完整时计算。移出列表只表示该商品本次未出现在同范围列表中。

首期围绕已知链接建立观察池。7 天和 30 天增量、关键词搜索采集、自动选品、笔记归因留作后续扩展。

## 2 用户流程与界面

1. **添加链接**。支持粘贴单条分享链接、多行链接和含链接的分享文案。后台解析后显示平台、类型、标题、可监控指标及建议频率。用户确认后入池。识别失败时可逐行修改，处理结果显示新增、已存在、格式不支持或待验证。
2. **查看监控池**。列表包含平台、标题、标签、最新指标、最后成功时间、任务状态和启停。支持按平台、类型、标签和变化筛选。小红书商品可按今日展示销量增量排序，闲鱼商品可筛选降价、已售状态变化或访问异常。
3. **查看目标详情**。展示时间线、快照、原链接、首次／最后成功采样、指标精度、触发记录及失败原因。商品按可用指标展示曲线，店铺或卖家主页展示已验证的店级指标。支持时间范围筛选和 CSV 导出。
4. **管理通知**。在规则页启停规则、改阈值、测试发送。通知记录显示触发依据、检测时间及渠道送达状态。运营可从消息进入详情或原页面。
5. **暂停与恢复**。暂停保留历史，恢复后从下一计划槽继续。手动刷新单独记录实测时间，服务端限频，用于诊断和核对。计划槽统计和小时预警继续按计划快照计算。

## 3 数据来源与平台适配

### 3.1 上线前样本验证

对每个平台准备 10–20 条商品链接及至少 3 条店铺或卖家主页链接。覆盖原始链接、短链、分享文案、重复链接、改价、已售、下架、访问限制、缺销量和模糊销量。逐字段记录访问来源、稳定 ID、显示名称、单位、精度、权限和失败状态。闲鱼重点确认已售或下架是否有明确页面语义，卖家列表是否具有可比的覆盖范围。小红书重点确认商品累计展示销量和店铺全店指标的来源及口径。

小红书官方文档按应用类目列出商品、订单等授权能力。闲鱼官方批量商品查询面向授权服务商。开放平台文档不能单独证明任意分享链接都具备可自动、持续读取的指标。首选项目实际可用且允许的 API 或数据来源。人工快照导入可先验证 Web、调度与统计链路，自动监控的上线需通过真实来源试采。

### 3.2 适配接口

平台适配器提供三个接口，输入输出采用统一 schema。

| 接口 | 输入与输出 |
| --- | --- |
| resolve | 输入分享 URL，输出 platform、target_type、external_id、canonical_url，或明确的解析失败原因 |
| capabilities | 输出目标可支持的指标、单位、允许的最短采样周期和可用规则 |
| observe | 输入已解析目标及任务上下文。输出 observed_at、access_status、listing_status、metrics、adapter_version 及脱敏诊断信息 |

目标身份由 platform + target_type + external_id 确定。短链和长链解析到同一 ID 时合并，保留用户标签和来源记录。链接批量解析走后台，限制每次跳转的目标域和总次数，拒绝本地、私网和内网地址。未能解析的链接进入待处理列表。禁止把解析来源返回的文本或 HTML 当作可执行内容渲染。

访问结果与商品状态分别建模。登录失效、限流、超时、字段缺失属于采样结果。已售或下架仅在来源明确返回时记录。短链失效时继续尝试已验证的规范链接。状态不可确认时保留最近已确认状态及时间，展示本次异常。两平台独立维护访问配额和故障状态。

## 4 架构与数据模型

建议前端 Vue 3 + ECharts，后端 FastAPI，数据库 PostgreSQL。部署 Web/API 和 Worker 两类服务。初期通过数据库任务表完成调度、租约与重试。平台差异由适配器处理，共享入池、计划、快照、指标计算和通知。

~~~text
Web 页面 / 可选 Windows 采集器
                ↓
        入池 API → 链接解析 → 监控池
                                ↓
                           调度与任务表
                                ↓
               Worker → 闲鱼或小红书适配器
                                ↓
                  快照 → 变化检测 → 通知发件箱
                   ↓                    ↓
              Web 历史与导出         微信 / 钉钉
~~~

| 表 | 关键字段与约束 |
| --- | --- |
| monitor_target | id、platform、target_type、external_id、canonical_url、title、enabled、schedule_id、capabilities。平台 + 类型 + 外部 ID 唯一 |
| target_source | target_id、input_url、keyword、import_batch_id、metadata。记录链接别名与采集器来源 |
| schedule_profile | 时区、商品时段或店铺固定时间、时窗。可按平台和目标类型启用配置 |
| sample_task | target_id、slot_at、state、attempts、next_run_at、lease_until、lease_version。计划任务按目标 + 槽位唯一 |
| snapshot | task_id、target_id、slot_at、observed_at、access_status、listing_status、adapter_version。一任务最多一条最终快照 |
| snapshot_metric | snapshot_id、metric_code、raw_value、numeric_value、lower_bound、unit、precision、quality。快照 + 指标编码唯一 |
| alert_rule / change_event | 平台、目标类型、指标、条件、阈值及版本。规则或变化事件保存起止快照和时间。目标 + 槽位 + 规则版本去重 |
| notification_outbox | channel、batch_key、message_id、status、attempts、next_run_at。渠道 + 批次分片唯一 |
| import_batch | id、idempotency_key、input_hash、status、result。重复提交返回原批次状态和逐条结果 |

按指标保存原始展示值。价格以整数分存储，展示区间单独保留。累计销量字段保留精确度。不可用指标为空，明确展示的 0 记为 0。时间戳存 UTC，查询和计划按 Asia/Shanghai 转换。给目标与槽位、任务状态与到期时间、事件时间分别建索引。

## 5 指标与提醒

### 5.1 小红书销量变化

- **小时增量**。仅比较同日相邻整点槽，建议实际采样间隔为 45–75 分钟。1000 → 1006 → 1013 得到 +6 和 +7。中槽缺失时可显示覆盖两小时的 +13，小时增量留空。
- **今日增量**。当前有效读数减前日 23:00 快照，页面显示基准时间及覆盖的夜间时段。缺前日结尾点时，单独展示当日首末点区间变化。**历史日增量**按相邻日固定结尾槽计算。店铺例 8280 → 8420，日差值 +140。
- **可比条件**。必须同来源、同口径、同单位、精确值且处于相同基线版本。初次采样建立基线。“5000+”保留原文及下界。回退标记数据异常，暂停跨异常点差值和提醒，复核后建立新基线。展示销量变化用于观察趋势。

### 5.2 闲鱼价格与状态变化

- **价格**。同币种、同价格语义且字段明确时计算差值。例如 59 元降到 49 元，记录下降 10 元。建议首期默认记录全部可确认变化，用户单独开启通知并设置最低降价额。
- **状态**。初次观察仅建立基线。比较最近两次有效状态。例如在售 → 已售触发一次状态事件，下一次仍为已售时不重复。中间有采样缺口时，记录首次发现时间与之前的观测时间。
- **访问异常**。将临时网络故障与商品状态变更分开。建议连续 3 次访问异常后生成运维提醒，恢复时更新状态。明确的访问限制触发来源级暂停和检查。

### 5.3 通知规则

| 规则 | 默认条件 |
| --- | --- |
| 小红书普通商品 | 最近一小时展示销量增加 ≥ 5 |
| 小红书高价商品 | 当前有效价格 ≥ 29 元，且最近一小时增加 > 1 |
| 闲鱼降价 | 用户启用后，降价金额达到配置阈值 |
| 闲鱼商品状态变化 | 用户启用后，出现所选且可确认的状态变化 |
| 访问异常 | 同目标或平台来源连续异常达到配置阈值，按类型汇总 |

同目标同槽命中多条规则时汇总到一个条目。消息含平台、名称、旧值、新值、检测时间、命中规则和可访问链接。小红书销量消息另带当前累计和今日增量。支持钉钉与实际可用的微信机器人接入。渠道网关超时且送达状态不明时保留待核查状态。可支持幂等的渠道使用稳定消息 ID。发件箱在事务内写入，后台异步投递并记录结果。

## 6 Web API

| 方法与路径 | 用途 |
| --- | --- |
| POST /api/v1/link-resolutions | 提交分享文案或链接列表，返回解析批次 ID |
| GET /api/v1/link-resolutions/{id} | 查看逐条结果、规范链接、目标类型和可用指标 |
| POST /api/v1/targets/batch | 确认入池或由采集器直接提交。支持 Idempotency-Key，同键不同请求返回 409 |
| GET /api/v1/targets | 按平台、类型、标签和状态分页。按指定指标排序，空值最后 |
| PATCH /api/v1/targets/{id} | 修改启停、标签或计划配置 |
| POST /api/v1/targets/{id}/refresh | 创建独立手动刷新任务，返回任务 ID |
| GET /api/v1/targets/{id}/series | 按日期范围和粒度返回快照、指标、变化和质量状态 |
| GET /api/v1/targets/{id}/series.csv | 按相同口径导出历史 |
| GET /api/v1/events | 查询销量、价格、商品状态和访问事件 |
| GET /api/v1/rules | 查询已配置规则 |
| PATCH /api/v1/rules/{id} | 更新阈值和启停配置，新版本从下一计划槽生效 |
| GET /api/v1/ops/runs | 查看各平台计划进度、失败原因和通知积压 |

批量接口建议每批最多 200 条。失败项保留输入序号和可操作错误码，例如 UNSUPPORTED_LINK、UNRESOLVED_TARGET 和 ACCESS_RESTRICTED。Web 账号与采集器令牌分开管理。本机部署默认回环监听。远程使用时启用 HTTPS、登录验证与管理接口权限检查。

## 7 调度与部署

调度器按平台计划创建到期任务，Worker 通过数据库行锁和带版本的租约领取。默认只在计划后 45 分钟内接受该槽快照，超时记缺采。短暂错误在时窗内退避重试，来源级限流独立控制，避免单个平台故障阻塞另一平台。快照、变化事件与任务完成状态在同一事务提交，租约过期后的旧 Worker 无权覆盖结果。批次通知在该轮结束或截点到达后生成。

沿用原文 2300 个小红书商品及 140 个店铺的基准，每日约 32,340 个计划槽。闲鱼新增负载按“商品数 × 每日商品采样次数 + 卖家主页数 × 每日主页采样次数”估算。计算每个平台的请求放大倍数和配额后，分别压测短链解析和采样。先用小样本测试数据源，再用模拟数据验证 2300+ 目标规模的任务恢复、去重及查询性能。

部署建议使用 Docker Compose 运行 Web、Worker、PostgreSQL。支持数据库备份、独立关闭某平台采样和停止通知。运行页追踪槽位完成率、字段缺失率、采样滞后、受限率和投递失败。凭证放服务端密钥配置，日志脱敏。

## 8 开发顺序与验收

| 阶段 | 验收 |
| --- | --- |
| 数据源验证 | 双平台真实样本可解析。同商品多种分享方式识别为同一 ID。闲鱼商品价格及状态逐条核验，小红书销量及店铺指标核对语义。明确每种目标可用指标和采样频率 |
| Web 与入池 | 同一批混合平台链接可正常入池。重复目标沿用原记录。坏链接有逐条原因。可启停、筛选、查看详情并导出 |
| 监控与计算 | 小红书验证小时 +6、+7、店铺日 +140、缺槽及“5000+”。闲鱼验证 59→49 元、在售→已售、重复状态去重、限流不误判下架、列表分页不全时禁止生成移出事件 |
| 预警与恢复 | 测试 +5 普通阈值、29 元和 +2 高价边界、同一商品双重命中汇总、闲鱼降价及状态变化。验证渠道送达、进程重启、任务重复领取和跨平台故障隔离 |
| 试运行 | 双平台分别接入少量真实链接连续运行 7 天。记录识别率、有效采样率和通知送达率，依据首周结果确认可支持的监控规模 |

当前设计假设闲鱼先以商品链接的价格和状态为主，卖家主页能力随样本验证启用。开工时以真实分享链接验证两平台来源，并确认闲鱼主要观察目标是否还需要“想要人数”或卖家可见商品变化。这些能力独立配置，已有小红书销量监控口径可继续复用。
