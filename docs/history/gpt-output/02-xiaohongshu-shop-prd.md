# 小红书商品与店铺销量监控项目开发技术文档

版本 1.0 · 开发评审稿 · 2026 年 11 月 22 日

## 1 项目目标与范围

把公开页面的累计销量定期保存下来，让运营人员能按今日增量筛选商品、查看小时和日趋势、发现连续增长的店铺，并在重点商品起量时收到提醒。监控结果用于决定下一步研究哪些关键词、店铺和笔记，由运营人员完成选品判断。

| 边界 | 首期交付 |
| --- | --- |
| 系统 1 · Windows 采集器 | 作为上游。沿用关键词搜索、店名或账号 ID 找店、整店采集及销量、价格、上新时间、数量等筛选。监控侧提供批量入池接口，支持手动录入或 CSV 导入 |
| 系统 2 · 本地 Web | 商品和店铺监控池、定时采样、快照与差值、趋势详情、预警规则、微信和钉钉通知、任务状态及导出 |
| 首期指标 | 商品累计展示销量、最近一小时、今日、昨日、历史日增量。店铺累计展示销量及相邻日差值 |
| 后续扩展 | 7 天和 30 天增量、关键词样本趋势、考试日历标注。首期保存所需历史与关键词关系 |

监控记录反映平台展示口径及其变化。真实订单、退款、GMV、成本和利润均不从公开展示销量推算。店铺总销量采用页面上语义明确的全店指标，支持店铺层面的趋势判断。

## 2 业务流程与页面

1. 运营从关键词或店铺发现候选，在采集器筛选后批量推送，也可在 Web 手动新增。提交结果逐条返回新增、已存在或失败原因。
2. 投入监控后，商品按时段采样，店铺每日采样。列表默认按可计算的今日增量降序排列，缺数排在有效数据后面。按关键词、店铺、价格、启停和采样状态筛选。
3. 商品详情展示原始销量文本、最近成功时间、小时和日曲线、预警记录及原链接。店铺详情展示每日总销量和相邻日差值，可查看该店已入池商品。跨槽差值标注覆盖时段，曲线缺口保留。
4. 单轮商品预警汇总后推送。运营通过消息打开详情，并复查持续性、同关键词其他商品、店铺及相关笔记。店铺持续上涨时，可回到采集器做整店采集。
5. 暂停后保留历史，后续不再生成该目标的新任务。恢复后仅执行当前及未来槽位，首条可作新基线。复用原监控记录和标签。

## 3 数据源接入与技术架构

### 3.1 数据源验证

原文给出了采样频率和展示指标，未给出页面访问方式、字段位置或可复用接口。接入阶段用 10–20 个商品和至少 3 个店铺建立样本，覆盖正常、已售 0、千位或万位缩写、下架、缺销量、链接失效及店铺总销量。逐一记录可用访问方式、稳定 ID、页面指标标签、单位、展示精度、价格含义和失败类型。样本需用可正常访问且平台允许的来源核验。人工记录或导入可用于验证处理链路，自动定时监控的验收仍需可持续使用的自动化数据源。

小红书电商开放平台的订单与商品能力按应用类目授权。项目的数据需求是公开可见的竞品展示指标，上线前按实际来源验证字段和可访问范围。仅有部分在售商品时，全店销量保持“不可获取”，避免误用部分商品累加。授权失效、访问受限或页面字段因版本变更消失时，暂停相应来源或目标并提示处理。

### 3.2 架构和建议技术栈

Windows 采集器 → 本地入池 API → 监控目标与标签  
调度器 → 任务表 → Worker → 数据源适配器 → 销量快照 → 差值与预警 → 通知发件箱  
Web 页面 → 查询 API → 监控池、销量趋势、预警及任务状态

建议 Python + FastAPI、Vue 3 + ECharts、PostgreSQL。部署为 Web/API 和后台 Worker 两类进程，共用数据库。调度器随 Worker 运行，通过数据库唯一键防止重复建槽，任务使用行锁与租约领取。首期个人使用默认绑定回环地址，可在 Windows 上登记为后台服务。后续拆分组件时复用 API、适配器与数据模型。

适配器输入为目标类型、平台 ID、规范链接及任务上下文，输出包括解析结果、销量原文、数值或下界、单位、精度、价格及采样时间，并返回可重试、授权失效、字段缺失、下架等结果。保留解析器版本和脱敏诊断信息。自动访问的并发和频率受来源额度约束，按来源配置。

## 4 指标计算口径

### 4.1 时段与计算规则

统一按 Asia/Shanghai 分槽，数据库时间戳存 UTC。商品每天 10:00 至 23:00 整点执行，含首尾共 14 个槽。店铺每天固定 1 次，建议默认 10:00，可全局调整。每个快照同时保存计划槽位和实际观测时间。以计划槽标记趋势，页面可查看真实时间。默认仅接受槽位开始后 45 分钟内的采样，任务超时后标为缺采。首期禁止用当前读数填补过去槽位。

| 指标 | 计算规则 |
| --- | --- |
| 当前总销量 | 最近一次有效展示值。同步失败时保留上次读数及时间，并展示过期或失败状态。缺字段与明确展示 0 分开记录 |
| 最近一小时新增 | 当日相邻整点槽都有精确读数，且实际采样间隔在 45–75 分钟内时，计算当前减前值。10:00 无同日上一槽，小时增量为空 |
| 今日新增 | 当前日最新有效点减前一日 23:00 结尾点。以跨日结尾差覆盖夜间变化。展示为“今日监控增量”，并显示起止时间。缺前一日结尾点时，可单独展示“今日观测区间增量”及当日首末点，标准今日增量仍为空 |
| 历史日增量及昨日新增 | 商品当日 23:00 减前日 23:00。店铺使用每日固定槽的相邻日读数。任一结尾槽缺失时，日增量为空。历史允许查看上次有效点差值及跨度 |
| 首次采样及长期断采 | 第一次仅建立基线。跨槽或跨日的有效点可展示覆盖区间的总变化，保持小时和日增量为空。按版本保留统计口径 |
| 模糊值与回退 | “5000+”存原文及下界，“1.2 万”等缩写保留展示精度。仅同来源、同指标、同单位且精确的点用于确定差值与预警。发现回退时标异常并断开基线，经复核后可开启新基线或修正来源，保留原快照与操作记录 |

验算：10:00 累计 1000、11:00 累计 1006、12:00 累计 1013，两段小时增量分别为 6 和 7。若 11:00 缺采，12:00 可显示两小时累计变化 +13，小时增量为空。店铺相邻日读数 8280→8420，日增量为 +140。教资案例中 5076→5250 对应 +174，存在相邻日快照时即可用作历史聚合的回归样本。

### 4.2 预警与推送

| 默认规则 | 触发条件 |
| --- | --- |
| 普通商品异动 | 最近 1 小时新增 ≥ 5 |
| 高客单价商品异动 | 当前有效价格 ≥ 29 元，且最近 1 小时新增 > 1 |

两条规则独立运行，支持启停和阈值编辑。人民币金额按整数分存储。高价规则使用该次采样的可比价格，缺价或只有价格区间时跳过该规则。普通规则仍继续评估。多个规则命中时，同商品同槽只展示一条，列出全部命中规则。缺采、计数回退、模糊值及日差值不会进入小时提醒。

按计划槽位汇总。该轮任务全部结束或到达截点后，按渠道上限拆包。消息包含商品名称、价格、当前总销量、今日新增、小时新增、命中规则、观测时间和详情链接。今日新增为空时写“暂无可比基准”。微信通过运营实际可用的机器人通知服务接入，钉钉通过可用的机器人通道接入，首期以实际测试送达为验收。手机端无法访问本机地址时，消息提供商品原链接或使用部署配置中的可达 Web 地址。

检测记录与待发送消息随事务入库。发件箱按渠道、轮次、分片唯一入库，通知重试复用原消息 ID。支持幂等键的供应商应传递该 ID。渠道超时且送达状态未知时，保留待核查状态，避免静默发生重复推送。管理页显示已送达、重试中或最终失败。

## 5 数据结构

| 表 | 关键字段与约束 |
| --- | --- |
| monitor_target | id、type、platform_id、canonical_url、shop_target_id、title、status、source、created_at。目标唯一键为平台 + 类型 + 平台 ID，短链解析统一 ID 后再入池。无法识别时记录导入失败或待人工处理 |
| target_discovery | target_id、keyword、collector_record_id、collected_at、metadata。保留同一目标的多关键词与多次来源，来源记录重复提交可去重。metadata 保存上游可选字段 |
| sample_task | target_id、slot_at、state、lease_until、attempts、next_run_at、last_error。唯一键为目标 + 槽位，索引 state + next_run_at |
| sales_snapshot | target_id、slot_at、observed_at、raw_sales、sales_exact、sales_lower_bound、unit、precision、price_fen、quality、source_version、baseline_version。目标 + 槽位唯一，按目标与槽位倒序访问 |
| sales_daily | target_id、biz_date、opening_snapshot_id、closing_snapshot_id、delta、quality、metric_version。目标 + 日期 + 口径版本唯一，支持按原快照重算 |
| alert_rule / alert_event | 规则阈值、启停及版本。事件存目标、槽位、命中规则、差值、入参快照。目标 + 槽位 + 规则唯一 |
| notification_outbox / import_batch | 发件箱存渠道、轮次、分片号、发送结果及下次重试时间。导入批次存幂等键、请求摘要、逐行结果。敏感渠道凭证由后台配置持有 |

上游 metadata 可接收来源关键词、店铺名、商品标题、价格、主图链接、销量展示、详情标记、加购信息、上架时间、商品链接、粉丝数量、开店时长、状态、备注和采集时间。未知值保持为空。上游采集数据用于补齐候选资料，进入定时序列的正式销量快照由监控侧按槽位生成。下架保留目标和历史。原始快照建议保留 400 天以便观察跨年季节性，试运行后根据磁盘和业务需要调整。

## 6 API 契约

| 方法与路径 | 用途 |
| --- | --- |
| POST /api/v1/targets/batch | 采集器批量入池，接受商品和店铺混合批次。建议每批最多 200 条，逐条返回索引、目标 ID、创建或已存在、错误码 |
| GET /api/v1/targets | 按类型、关键词、店铺、状态、日期筛选。默认 50 条，稳定排序为有效今日增量降序、ID 升序。返回最近采样、指标质量和更新时间 |
| PATCH /api/v1/targets/{id} | 调整启停、备注及运营标签。已有目标重复导入时补充来源关系，保留人工维护的状态和字段 |
| GET /api/v1/targets/{id}/series | 参数 from、to、granularity。返回槽位、观测时间、原始读数、差值、基准时间和质量状态 |
| GET /api/v1/targets/{id}/series.csv | 使用同一查询口径导出时间序列，保留空值、原始展示及异常说明 |
| GET /api/v1/alerts | 按目标、规则、时段及发送状态查询预警 |
| GET /api/v1/alert-rules | 获取当前规则及生效版本 |
| PATCH /api/v1/alert-rules/{id} | 校验并更新阈值或启停，新版本从下一槽生效 |
| GET /api/v1/ops/runs | 查看槽位进度、成功率、失败分布、积压及通知异常 |
| POST /api/v1/ops/tasks/{id}/retry | 重试仍在有效时窗内的失败任务，已过窗时返回明确原因 |

入池端口默认回环监听，采集器使用独立 Bearer token。入池请求携带 Idempotency-Key。同一键和同一请求返回原结果，同一键配不同请求返回 409。系统只接受已支持的平台链接或可验证的平台 ID，限制解析跳转范围，分配目标 ID 前完成类型和字段校验。

~~~json
{
  "items": [
    {
      "type": "product",
      "platform_id": "example-product-id",
      "title": "成人高考专升本资料",
      "keywords": ["成人高考", "专升本"],
      "price_fen": 2900
    },
    {
      "type": "shop",
      "platform_id": "example-shop-id",
      "title": "店铺 A"
    }
  ]
}
~~~

## 7 调度容量与运行保障

按原文 2300 个商品和 140 个店铺估算，每日计划采样约 32,340 次，一年约 1180 万条快照（按每目标每槽成功一次且规模稳定估算）。店铺默认与 10:00 同轮时，峰值 2440 个目标。若目标为 30 分钟完成，需约 1.36 个目标每秒。设每目标平均耗时为 t 秒，则所需平均并发约 1.36 × t，实际并发须依据来源限额、每目标请求数、重试和数据源压测确定。若来源配额不足，优先确认允许的访问容量，再由运营调整监控池或时段。

- 调度器每分钟补建当前有效时窗内到期槽位。任务状态为待执行、执行中、成功、待重试、失败或错过。Worker 通过租约竞争领取和续租，进程中断后，未过期任务可由其他 Worker 接管。提交时校验租约版本，防止旧 Worker 覆盖成功结果。
- 网络瞬断和明确的临时服务错误退避重试，耗尽时窗后标记缺采。访问受限或来源异常时降低速率或暂停该来源。下架、缺字段和授权失效分别展示，字段缺失率异常时运维检查适配器。
- 在同一数据库事务写入快照、更新聚合和预警候选并标记任务完成。唯一约束负责去重。消息发送独立于采样流程，多进程重试或重启可恢复。
- 监控每轮完成率、精确值比例、积压、采样滞后、计数回退和消息失败。建议试运行目标为 30 分钟内完成 95% 的到期任务，7 天内对有效数据源目标的计划槽成功率 ≥ 95%。无数据、下架、受限各自计数，避免以减少分母掩盖缺采。
- 以槽位时间索引并巡查查询计划。按容量测试确定快照分区和清理批次。每日备份数据库，发布前演练恢复。通知凭证加密保存并脱敏日志。外网部署时启用鉴权和 HTTPS，限制管理端及导出权限。

## 8 开发顺序与验收

| 阶段 | 完成条件 |
| --- | --- |
| 数据源验证 | 样本商品及店铺字段可核对，展示总量、店铺范围、精度和来源限制有记录。无可靠来源的目标可显示不可获取 |
| 入池与采样 | 手动及批量入池跑通，重复导入不增目标，商品 14 槽与店铺 1 槽准确，首次、暂停、恢复、失败重试和进程重启均可复现 |
| 统计与界面 | CPA 连续日读数 1289→1311 验证 +22，教资 5076→5250 验证 +174。验证跨夜、漏槽、近似值、真实 0、下架及回退。列表正常排序，曲线保留缺口，导出与页面一致 |
| 预警与可靠性 | 普通规则 +4 未触发、+5 触发。高价规则验证 28.99 元与 29 元、+1 与 +2 的边界。双规则命中只展示一个商品条目。重复任务不重复入库。测试微信和钉钉实际送达与渠道失败恢复 |
| 压测与试运行 | 用 2300 商品和 140 店铺等量数据模拟峰值与重启，用允许访问的真实样本验证字段和新鲜度。按既定时窗与来源配额验收，试运行连续 7 天后决定扩量 |

上线前确认实际数据源和店铺总销量字段、今日增量日界、建议采样时窗、微信接收通道及数据保留期。上线回退时可关闭调度和通知，保留查询、历史及未发送记录，修复后仅恢复仍在有效时窗内的任务。
