# 开发过程记录

这个目录保留了项目从需求到当前版本的两轮完整过程，用途是回答「当时为什么这么做」——文档和代码只写得出现在是什么，写不出否决过什么方案、踩过什么坑。

## 内容

| 文件 | 是什么 | 规模 |
|---|---|---|
| `gpt-output/01-xianyu-xiaohongshu-prd.md` | GPT 阶段产出的第一份技术文档：闲鱼 + 小红书 Web 链接监控整体方案 | 约 1.5 万字符 |
| `gpt-output/02-xiaohongshu-shop-prd.md` | 第二份，聚焦小红书商品与店铺的销量口径 | 约 1.6 万字符 |
| `01-gpt-codex-development.md` | GPT（Codex 桌面端）实现阶段的对话流程 | 1985 行 |
| `02-workbuddy-continuation.md` | WorkBuddy 接手阶段的对话流程 | 1098 行 |

两份 PRD 是**需求基线**，不是最终实现。最终实现与它的差异，在 `docs/TECHNICAL.md` 里有说明（例如闲鱼店铺后来被证明可以无需登录采集，与最初判断不同）。

## 对话记录的提取口径

原始日志是运行时的 JSONL（Codex 11 MB、WorkBuddy 3.5 MB），包含大量工具输出与内部推理，直接读没有意义。这里做了三步处理：

1. **保留**：用户需求原话、助手的判断与说明文字、每次工具调用的名称与参数首行
2. **丢弃**：推理过程、工具原始输出（命令回显、文件内容、网页正文）、系统注入的上下文
3. **脱敏**：访问密码 → `<PASSWORD>`，云开发环境 ID → `<TCB_ENV_ID>`，线上域名 → `<SERVICE_URL>`

因此这是**可读的流程记录，不是逐字原始日志**。需要核对某次具体操作细节时，原始 JSONL 在项目负责人的本机：

- Codex：`~/.codex/sessions/2026/11/22/rollout-2026-11-22T04-04-49-*.jsonl`
- WorkBuddy：`~/.workbuddy/projects/.../fa58c49c-*.jsonl`

## 怎么用

- 想知道某个设计怎么来的 → 搜关键词，看该时间点前后的助手说明
- 想知道某次线上故障怎么处理的 → 搜 `RGV587`、`清库`、`恢复`
- 想知道当时试过但放弃的方案 → 搜 `不可行`、`失败`、`放弃`

## 注意

记录里的时间都是北京时间。命令中的路径是原开发机的绝对路径（`F:\codebase\...`、`C:\Users\...`），换机器后不适用；要复现请看 `docs/OPERATIONS.md`。
